# 作品の分割保存

通常の作品保存は、作品本文を1作品ずつのJSONへ分割し、小さな一覧ファイルで参照します。
Androidの内部保存先は `filesDir/work-store/`、選択した外部保存フォルダでは `edit-rin-works/` を使用します。

```text
edit-rin-works/
  index.json
  index.json.backup
  <作品IDのSHA-256>-<本文のSHA-256>.json
  ...
```

- 本文にはコード、補助ファイル、素材への参照、実行設定、パラメータ値、作品情報、従来の小さな変更履歴を保存します。
- 一覧には本文ファイル名、作品ID、名前、日時、ピン留め、タグ、保存時の選択作品、実行設定や補助ファイル名の軽量情報を保存します。
- 保存済みの値と比較し、変更した作品の本文だけをJSON化・書き込み・読み戻し検証します。未変更の作品の本文は再保存しません。
- 内容が変わらない保存では書き込みを省略します。コードのみ変更した場合、外部フォルダの素材同期も省略します。
- 起動時は一覧と選択作品の本文を先に読み込み、他の本文は作品選択時に読み込みます。下書きの照合に必要な作品と全体バックアップでは必要な本文を読み込みます。
- 情報が不足する旧一覧は一度全本文を読み、次の保存で新しい一覧へ更新します。未読の本文を空コードとして保存することはありません。

## 保存と復旧

変更した本文は新しいファイルとして書き、読み戻しが一致することを確認します。その後、一覧の `.pending` を書き、検証してから一覧を切り替えます。
前回の一覧と、それが参照する本文を保持します。一覧や本文が不完全な場合は、前回の完全な作品群を読み込みます。
ファイル名と本文のSHA-256、作品IDの一致も検証します。どちらの作品群も読めない場合は、新しいデータで上書きしません。
保存失敗時は編集中のコード、選択作品、補助ファイルの下書き、Undoを維持します。

外部で一覧が変更された場合、通常の再試行でも上書きしません。「外部変更と統合」で未編集作品には外部変更を反映します。同じ作品に両側の変更がある場合、編集中の内容を新しいIDの別作品として保持します。統合保存に失敗した場合も編集を保持し、再試行で競合保護を解除しません。

下書きには保存先と編集開始時の本文ハッシュを保存します。保存先・作品・本文が一致する場合だけ自動復元します。一致しない下書きは自動適用せず、「別作品として復元」または明示的な破棄を選択できます。

通常保存が成功した後、現行・前回の一覧のどちらからも参照されなくなった古い本文を整理します。
素材の整理でも復旧用一覧の参照を保護します。

## 旧形式からの移行

分割形式が存在しない場合に、従来の内部 `local-works.json` または外部 `hikari_atelier_works.json` を読み込み、自動移行します。
移行後の本文を読み戻し検証し、旧ファイルは移行前の保管データとしてそのまま残します。以後の編集は分割形式へ保存し、旧ファイルは更新しません。
移行の書き込みに失敗した場合も、読み取り可能な旧データは利用でき、後の保存で移行を再試行します。
分割形式の現行・前回データが両方壊れている場合は、古い一括ファイルへ勝手に戻して作品の削除や編集を取り消すことはしません。

ZIP書き出し・取り込みでは従来の `works.json`、素材、スナップショットの形式を維持します。全体バックアップには `templates.json` と自作テンプレートの素材も含めます。旧ZIPにテンプレートが含まれない場合、既存テンプレートを保持します。単体作品ZIPにはテンプレートを含めません。
旧版アプリで分割フォルダを直接利用することはできません。端末間の移動にはアプリのZIP書き出しを利用してください。
