# 最適化デバッグ版：実機確認手順

対象：Edit:RiN Dev / com.hikariatelier.app.debug / 2.0.7-runtime-debug

この手順は実機確認の計画です。手順の作成やローカルテストの成功は、実機での動作確認完了を意味しません。

## 準備

- 既存のDev版に作品がある場合は、先にZIPバックアップを作成してください。今回のAPKは既存Dev版への更新です。通常版とは別のアプリIDですが、同じ外部フォルダーを選ぶと作品ファイルを共有するため、検証にはコピーした専用フォルダーを使ってください。
- アプリのアンインストールやデータ消去は不要です。
- `large-sketch.js` は長文編集・検索・パラメータ・ログ・PNGの確認に使えます。新しい作品としてJSインポートしてください。
- まず端末内保存で確認し、その後に外部フォルダーで同じ保存操作を確認してください。
- 問題が出た段階で後の試験を止め、手順・作品・端末名・Android/WebViewバージョン・スクリーン録画を記録してください。

## 1. 最初に保存・復元を確認する（最優先）

1. 検証用作品Aを作り、メインコードに `// SAVE_A` を追加して保存します。
2. 補助ファイル `helper.js` を作り、`const helperValue = 123;` を保存します。
3. メインコードと補助ファイルを編集して保存し、作品Bへ移動してからAへ戻ります。
4. アプリを終了して起動し直し、両ファイルの内容が残っていることを確認します。
5. Aだけを変更したとき、Bのコード・素材・タグ・ピン留めが変わらないことを確認します。
6. ライブパラメータや縦横比を変更し、直後にBへ切り替えてAへ戻します。変更が残ることを確認します。
7. 保存中にも追加入力できる場合は追加入力します。保存済み表示で追加入力を失わず、次の保存または作品切り替え後にも残ることを確認します。

**合格条件：** メイン・補助ファイル・パラメータが保持され、別作品に影響しない。未保存の追加入力とUndoが失われない。

### 保存失敗も確認できる場合

取り外し可能なUSB保存先など、検証専用の場所を使用します。最初の正常保存後、書き込み中ではない時点で保存先を利用不能にし、コードを編集して保存／作品切り替えを試します。

**合格条件：** エラーが表示され、編集内容・選択中の作品・Undoが保持される。保存先を再接続して再試行すると保存できる。主な作品の保存先では実施しないでください。

## 2. 次に長文入力・折りたたみを確認する

1. `large-sketch.js` を開き、先頭・中央・末尾で文字入力、改行、削除を各10秒程度試します。
2. 複数の `blockXXXX()` を折りたたみ、その外側の行を編集します。
3. 折りたたんだ箇所を展開し、内容が欠けていないことを確認します。
4. Undo／Redo、複数行選択、日本語IMEの変換確定、行番号、折り返しON／OFFを確認します。
5. 補助ファイルを追加してそれぞれ別の位置までスクロールし、タブを往復します。横スクロールは折り返しOFFで確認します。
6. 縦画面と横画面を切り替えます。

**合格条件：** 入力やカーソル移動が長く止まらない。行番号と本文がずれない。折りたたみでコードが消えない。タブごとの閲覧位置が保持される。

## 3. 検索・置換を確認する

1. 「現在のファイル」で `OPT_MARK` を検索します。未編集の検証ファイルには350件あります。
2. 「次へ」「前へ」を連続で押し、最後と最初を循環できることを確認します。
3. 検索文字を素早く変え、大文字・小文字の区別を切り替えます。古い検索結果に移動しないことを確認します。
4. `OPT_MARK` を `REPLACED` に「すべて置換」します。`OPT_MARK` が0件になることを確認します。
5. Undoで350件に戻り、Redoでもう一度置換されることを確認します。
6. 「作品全体」でメインと補助ファイルの一致箇所へ移動できることを確認します。

**合格条件：** 検索中も操作できる。表示件数・移動先が正しい。全置換が一度のUndoで戻る。

## 4. 作品切り替え・読み込み表示を確認する

1. 軽い作品と重い作品を、未編集の状態で10回ほど往復します。
2. 通常の未編集切り替えで「保存中」が出ないことを確認します。
3. 読み込みに時間がかかる場合、読み込み表示が出て描画完了後に消えることを確認します。利用できるサムネイルがある場合は直前の作品画像が一時表示されます。
4. 全画面への出入り、回転、一時停止・再開、ホームへ戻って復帰を試します。
5. 意図的な構文エラーを入れて実行し、エラー表示を確認した後、修正して再実行します。

**合格条件：** 別作品のコードが実行されない。読み込み表示が完了後も残らない。再実行で正常描画に戻る。

描画プロセスの異常終了が実際に発生した場合は、アプリを終了せず「再読み込み」で復帰することも確認してください。通常のJavaScript構文エラーとは別の経路です。無限ループやメモリを使い切るコードによる強制再現は不要です。この経路は別途、実機での開発者検証対象です。

## 5. ログが多い状態を確認する

1. 検証作品の「ログ出力」パラメータをONにして10秒ほど動かします。
2. コンソールを開き、スクロール・編集・停止の操作ができることを確認します。
3. 「ログ出力」をOFFにしてログを消去します。消去前の保留ログが後から戻らないことを確認します。
4. 必要なら検証コピーの `draw()` に `throw new Error('test error');` を入れ、エラーが速やかに表示されることを確認し、Undoで戻します。

**合格条件：** 通常ログはまとめて更新されるがエラーはすぐ表示される。作品切り替えや消去で以前の保留ログが混ざらない。

## 6. PNG・録画・共有を確認する

1. 検証作品を描画し、1倍・2倍・4倍でPNGを書き出します。この作品は600×400、pixelDensity(1)なので、600×400、1200×800、2400×1600が期待値です。
2. 保存した画像を端末の画像アプリで開き、サイズ・内容・透明／真っ黒になっていないことを確認します。
3. 一時停止した状態でも出力し、完了後に勝手に再生されないことを確認します。
4. PNG保存中に回転またはホームへ移動し、復帰後に保存状態が解除され、もう一度撮影できることを確認します。
5. MP4・GIFを各5秒録画し、端末で再生します。
6. シェアカードの画像が生成できることを確認します。外部への投稿は不要です。
7. 手元のWebGL作品でもPNGを試します。

**合格条件：** PNGの実寸が正しい。保存後に描画状態・解像度が戻る。失敗後も再試行できる。録画・シェアカードの画像取得が壊れていない。

## 7. 設定・ギャラリー・外部フォルダーを確認する

1. 設定の各カテゴリを別の位置までスクロールし、カテゴリを往復して位置が戻ることを確認します。
2. ギャラリーのメニュー、ピン留め、タグ操作をタップし、隣の操作を誤って押さずに使えることを確認します。
3. 端末の文字サイズを大きくした場合と横画面でも、ボタンやタイトルが重ならないことを確認します。
4. 検証用の外部フォルダーに作品と画像素材を保存し、作品を編集して再保存します。
5. アプリを起動し直し、素材を読み込めることを確認します。可能なら別のフォルダープロバイダーでも試します。
6. 最後にZIPバックアップ→別の検証環境へインポートし、コード・補助ファイル・素材・履歴が揃うことを確認します。

## 開発者向けの記録（ADB接続を許可した場合のみ）

今回の作業ではADB接続や端末操作を実施していません。以下は利用者側で接続を許可して実行する場合の参考です。

```sh
# アプリ全体のログ（別ターミナルで取得し、試験後にCtrl+C）
adb logcat -v threadtime > edit-rin-device-log.txt

# プレビュー準備時間のデバッグログだけを見る
adb logcat -s EditRiNPreview:D
```

`Preview ready in ... ms` は読み込み開始からsetup後の描画フレーム通知までの時間です。端末画面への実際の表示完了や全アニメーションの滑らかさを直接測定した値ではありません。

性能比較は同じ端末・同じ作品・同じ画面向き・同じ保存先で、初回と2回目以降を分けて記録してください。改善前後で各10回程度の切り替え・検索・保存を行うと比較しやすくなります。
